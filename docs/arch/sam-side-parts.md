# SAM: побочные части — согласие, дисклеймер, уведомления, права

Блок 25. Владелец — Игорь. Зависит от контракта SAM (блок 15).

## Согласие на обработку данных

- Модуль: `client/src/shared/lib/consent.ts`.
- Хранит выбор в `localStorage` (`hackathon-consent`): необходимые cookie всегда,
  аналитика — только после явного согласия.
- API: `readConsent`, `writeConsent`, `analyticsAllowed`.
- Баннер: `client/src/shared/ui/CookieBanner.tsx`. Две равнозначные кнопки:
  «Только необходимые» и «Принять все», ссылка «Подробнее» → `/cookies`.
- Страницы: `/terms`, `/policy`, `/consent`, `/cookies`
  (`client/src/features/legal/LegalPage.tsx`). Тексты — через Paraglide.
- Подключение аналитики в проекте нет, поэтому согласие не включает сторонние SDK.

## Дисклеймер демо-данных

- Виден на всех страницах `/sam`: `SamLayout` показывает
  «Демонстрационные данные» и пояснение про синтетические места, цены и `last_used`.
- Описание происхождения: `demo/sam/README.md`.
- Каждая строка `demo/sam/installed_software.csv` помечена `is_demo=true`.

## Уведомления о критических рисках

- Компонент: `client/src/features/sam/SamNotifications.tsx`.
- Источник: публичный `/api/public/sam/compliance`,  severity `high`/`critical`.
- Дедупликация: ключ `code + product + asset`; прочитанные ключи хранятся в
  `localStorage` (`hackathon-sam-notifications-seen`), лимит 200.
- Повторный заход на страницу не показывает уже прочитанное; кнопка
  «Отметить прочитанным» сбрасывает текущий список.
- Email/чат-доставка не реализованы: в демо-контуре уведомление живёт в интерфейсе.
  Для продакшена нужен отдельный транспорт и таблица доставки.

## Роли доступа

| Роль | Права |
|---|---|
| Неавторизованный | только публичные read-only SAM-проекции (`/api/public/sam/*`) |
| Участник (аналитик) | чтение SAM, запуск AI-ассистента и предложений оператора |
| Администратор | apply/undo оператора, управление пользователями и настройками |

- Публичные SAM-эндпоинты не принимают записи: `server/internal/sam/handler.go`.
- Оператор: `apply`/`undo` требуют администратора, `propose` — авторизованного
  участника (`server/internal/sam/operator/*`).
- Права проверяются в тестах SAM и в чек-листе ниже.

## Чек-лист проверок

```bash
# клиент и данные
bun run check
bun run typecheck:client
bun run build:client

# сервер SAM
cd server && go test -p 1 ./internal/sam/... && go vet ./... && go build ./...

# миграции
goose -dir migrations postgres "$TEST_DATABASE_URL" up
goose -dir migrations postgres "$TEST_DATABASE_URL" down

# ручная проверка
# 1. Открыть /sam: виден дисклеймер и панель уведомлений.
# 2. Очистить localStorage hackathon-consent: баннер появляется снова.
# 3. Выбрать «Только необходимые»: аналитика не запрашивается.
# 4. Открыть /terms, /policy, /consent, /cookies: тексты есть, ссылки в подвале работают.
# 5. Создать критический риск в комплаенсе: уведомление появляется один раз;
#    после «Отметить прочитанным» не появляется повторно.
# 6. Проверить, что публичный SAM API не принимает POST/PUT/DELETE без сессии.
```

## Ограничения

- Согласие хранится только в браузере; серверного журнала согласий нет.
- Уведомления не уходят во внешние каналы (email/чат) — только интерфейс.
- Дисклеймер и документы не заменяют юридические документы заказчика.
