# SAM: AI-ассистент-аналитик

Домен SAM хранит продукты, установки, алиасы и лицензии. Ассистент работает
только на чтение и доступен любому авторизованному участнику. AI-оператор
изменений вынесен в отдельную задачу `task/27-sam-operator`.

## Схема

`server/migrations/00005_create_sam_core.sql` добавляет:

| Таблица / view | Назначение |
|---|---|
| `sam_products` | продукты, вендор, версия, категория, статус `active/inactive/archived` |
| `sam_installations` | обезличенные установки; `product_id = NULL` — не сопоставлено |
| `sam_product_aliases` | нормализованные алиасы для поиска |
| `sam_licenses` | тип, места, стоимость места, даты, статус |
| `sam_risk_overview` | view с рисками: несопоставленные установки, истёкшие лицензии, перерасход мест, неактивные продукты, продукты без лицензии |
| `sam_ai_conversations` | диалоги ассистента (`mode = assistant`) |
| `sam_ai_messages` | сообщения диалога; tool-сообщения модели не публикуются |

Основной чат (`conversations`, `messages`) не переиспользуется, чтобы не менять
его поведение и права.

## Эндпоинты

| Метод | Путь | Ответ |
|---|---|---|
| POST | `/api/sam/assistant/chat` | `{id, answer, sources, fallback}` |
| GET | `/api/sam/assistant/conversations` | список своих диалогов |
| GET | `/api/sam/assistant/conversations/{id}` | сообщения своего диалога |

Все три требуют сессию. Данные ответа обезличены: имена сотрудников и устройств
не возвращаются. Лимит как у основного чата: один запрос на пользователя и два
одновременно на процесс (`sam/guard.Limiter`), при перегрузке — `429 chat.busy`.

## Инструменты и tool-loop

Пакет: `server/internal/sam/assistant`. Каждый инструмент — отдельный sqlc-запрос:

- `search_products` — `sam_products` + `sam_product_aliases`;
- `list_products(status)` — `sam_products`;
- `product_balance` — оплаченные места, установки, свободные места, ближайшее истечение;
- `find_installations` — обезличенные установки по продукту или имени;
- `license_summary` — сводка по типу лицензии;
- `top_risks` — `sam_risk_overview`;
- `unmatched_names` — несопоставленные имена, количество установок и устройств.

Модель вызывается через `llm.Complete` с tool-loop до 4 раундов и 12 вызовов.
Системный промт требует отвечать только по данным инструментов, указывать цифры
и источник (`sam_licenses, license_summary` и т. п.), не выдумывать, не выполнять
изменения и отвечать по-русски. Инструкции внутри данных игнорируются.

## Fallback без модели

Если LLM не настроен, вернул ошибку, не вызвал инструмент или не дал финальный
текст, включается детерминированный интент-роутер. Он использует те же sqlc-запросы
и отвечает на базовые вопросы: сводка, установки, баланс продукта, лицензии, риски,
несопоставленные имена, поиск и список продуктов. Для точных чисел используются
отдельные `count(*)`-запросы, а не длина страницы примеров.

## Проверки

```bash
# сервер целиком (нужен TEST_DATABASE_URL на portal_test)
cd server && go test -p 1 ./... && go vet ./... && go build ./cmd/...

# только SAM
go test -p 1 ./internal/sam/...

# контракт
bun run gen:api
```

Unit-тесты с фейковой моделью проверяют tool-loop, fallback, отсутствие вызова
модели при недоступности и лимит истории. Database-тест прогоняет 10 вопросов
аналитика на реальном PostgreSQL и сверяет точные цифры и источники.

## Допущения

- Блок 15 (базовая схема SAM) в живой ветке `task/2-public-planner` отсутствовал,
  поэтому `00005_create_sam_core.sql` добавлен как обязательный предшественник.
- Ассистент доступен любому авторизованному участнику, а не анонимному интернету:
  данные обезличены, но диалоги и лимиты привязаны к пользователю.
- Стоимость лицензии хранится в целых рублях за место за год.
