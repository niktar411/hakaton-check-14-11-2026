# AI-чат: архитектура

Подсистема чата превращает запрос в план/решение и (опционально) в coding-задачу.
Модель — DeepSeek V4.1 Flash через `server/internal/llm`; чат не выполняет код и
не меняет файлы сам.

## Экраны и страницы

- `/chat` — интерфейс чата (`client/src/features/chat/ChatPage.tsx`):
  вкладки «Чат» / «Агент», история диалогов, вложения, голосовой ввод,
  карточка запуска coding-агента (`AgentRunCard`), поповер контекста.
- `/chat` доступен только после локального входа участника.

## Фазы диалога

Диалог всегда начинается с фазы уточнения и не может её пропустить:

1. **Уточнение** — модель задаёт 1–3 вопроса по требованиям. Системный промт
   запрещает писать реализацию и выполнять команды.
2. **Решение** — следующее сообщение пользователя переводит диалог в решение.
   Модель даёт план, конкретное решение и перечисляет допущения.

Фазу уточнения можно пропустить фразой «продолжи работу на свое усмотрение»
(и близкими вариантами). Если в истории уже есть ответ ассистента, следующий
запрос сразу уходит в решение.

## Эндпоинты

| Метод | Путь | Что делает |
| --- | --- | --- |
| POST | `/api/chat/stream` | стрим решения через Server-Sent Events |
| POST | `/api/chat` | блокирующий вариант того же запроса |
| POST | `/api/chat/agent` | превращает решение в coding-задачу |
| GET | `/api/chat/conversations` | список диалогов пользователя |
| GET | `/api/chat/conversations/{id}` | история диалога |
| GET | `/api/chat/updates` | непрочитанные промпты о выполненных блоках |
| POST | `/api/chat/updates/{id}/pull` | помечает промпт прочитанным и сбрасывает кэш снапшота проекта |

Все эндпоинты требуют сессию участника (`identity.Principal`).

## Автоподтягивание изменений

Когда MR блока слит в основную ветку, `plannerblocks` при первом таком наблюдении
(`populateProgress` → `ProgressDone`) ставит блоку `completed_at` и создаёт ровно
один промпт в `chat_change_prompts` для каждого участника, кроме владельца.
Уникальный индекс `(block_id, username)` делает повторную раздачу невозможной,
гонки исключены условием `WHERE completed_at IS NULL`.

Клиент `/chat` опрашивает `/api/chat/updates` каждые 15 секунд и показывает
карточку (`ChatUpdateCard`): название блока, владелец, ветка, описание, ссылка
на MR. Кнопка «Подтянуть» вызывает pull-эндпоинт, сбрасывает кэш снапшота
репозитория (следующий ход модели видит свежее дерево и план) и отправляет в
текущий разговор готовый промпт с изменениями и ссылкой на MR. Повторный pull
возвращает 404 `chat.update_not_found`.

## SSE-стрим

`POST /api/chat/stream` отдаёт события:

| Событие | Содержимое |
| --- | --- |
| `meta` | `id` диалога и текущая фаза |
| `reasoning` | поток рассуждений модели |
| `content` | поток финального текста |
| `error` | код ошибки: `model.*`, `storage.unavailable`, `model.empty_response` |
| `done` | завершение: `id` диалога и фаза |

Финальный ответ сохраняется в БД так же, как в блокирующем `/api/chat`.
Повтор запроса блокируется по `request_id` (`chat.request_already_used`),
usage пишется в `usage_events`.

## Лимиты

| Ограничение | Значение |
| --- | --- |
| Длина промта | 16 000 символов |
| Суммарный контекст диалога | 100 000 символов |
| Личный контекст пользователя | 16 000 символов |
| Тон пользователя | 2 000 символов |
| Приложенные файлы | до 3, по 200 КБ и 12 000 символов каждый |
| Ответ модели | `max_tokens = 4096` |
| Параллельные запросы | 1 на пользователя, 2 глобально (`chat.busy`) |

## Сборка контекста

Системный промт собирается из (см. `server/internal/operations/chat_context.go`):

1. **Инструкция фазы** — уточнение или решение.
2. **`AGENTS.md`** — инструкции проекта, читаются с диска (монтируются в контейнер).
3. **Снимок проекта** — план команды из БД, дерево репозитория (до 220 файлов)
   и ключевые файлы (`CLAUDE.md`, `README.md`, `package.json`, `server/go.mod`).
   Снимок кэшируется на минуту и ограничен 24 000 символов.
4. **Общий контекст** — редактируется администратором в `/admin`
   (`chat_general_context`), до 16 000 символов.
5. **Личный контекст и тон пользователя** — из профиля участника.

Модель не получает SQL, секреты и `.env`; она не выполняет команды сама —
предлагает команды, файлы и проверки.

## Coding-агент из чата

`POST /api/chat/agent` создаёт coding-задачу и сразу подтверждает её:
агент работает в изолированном рабочем дереве, гоняет проверки, пушит ветку и
открывает MR, но не мержит и не деплоит. Слоты и лимиты те же, что у чата.

## Ошибки

| Код | Причина |
| --- | --- |
| `auth.required` | нет сессии |
| `model.not_configured` | не задан ключ модели |
| `model.access_denied` / `model.insufficient_funds` / `model.unavailable` | провайдер модели |
| `chat.busy` | слот занят |
| `chat.request_already_used` | повторный `request_id` |
| `chat.start_new` | контекст диалога превысил лимит |
| `chat.invalid_request` | невалидное тело запроса |
