# Сценарий демонстрации (5 минут)

Подготовка: сайт доступен, два аккаунта участника, ключ модели активен
(`modelReady: true`), CI зелёный. Два браузера или окна: «Пользователь A» и
«Пользователь B». В SAM демо-данные — обезличенные, места и `last_used` — синтетика
(`demo: true`).

## 0:00–1:00 — постановка задачи в чате

1. Пользователь A открывает `/chat`, вкладка «Чат».
2. Формулирует задачу: «Сделай на странице плана прогресс по блокам и мобильную
   вёрстку 375px».
3. Модель отвечает уточняющими вопросами (один раунд).
4. Пользователь A отвечает и подтверждает переход к решению.

Ожидаемо: уточнения краткие, реализация не пишется.

## 1:00–2:00 — решение и coding-агент

1. Пользователь A переключается на вкладку «Агент» и отправляет решение
   (или жмёт «Создать задачу»).
2. В карточке `AgentRunCard` видно статус задачи: `running → checks → MR`.
3. Агент работает в изолированном рабочем дереве, гоняет проверки и открывает MR.

Ожидаемо: статус задачи не висит, MR появляется, деплой не запускается сам.

## 2:00–3:00 — второй участник подтягивает изменение

1. Пользователь B открывает `/planner`, находит блок и видит обновление.
2. В чате пользователя B приходит уведомление о завершении блока.
3. Нажатие «Подтянуть» показывает изменение; повторного промта нет.

Ожидаемо: событие доставляется один раз, дублей нет.

## 3:00–4:00 — SAM: данные и комплаенс

1. Открыть `/sam`: виден дисклеймер «Демонстрационные данные» и панель
   уведомлений.
2. `/sam/inventory`: устройства `PC-0001…`, 24 589 строк, обновления помечены
   и не считаются лицензируемым ПО.
3. `/sam/compliance`: баланс «куплено против установлено», риск в рублях,
   запрещённое ПО (Radmin) — критический риск.
4. `/sam/matching`: кандидаты с confidence, подтверждение одного из них.

Ожидаемо: цифры совпадают с `demo/sam/summary.json`, дубли уведомлений нет.

## 4:00–5:00 — SAM: ассистент и оператор

1. `/sam/assistant`: «Какой запрещённый софт установлен?» — ответ по данным
   со ссылкой на отфильтрованный экран.
2. `/sam/assistant` (оператор): «Сопоставь все хромы с Google Chrome» —
   preview, подтверждение, аудит; повторный apply не меняет данные второй раз.
3. При недоступной модели включается детерминированный fallback — числа остаются.

## Что показать в конце

- Планер с прогрессом и MR.
- Два пользователя видят одно и то же состояние.
- SAM-дашборд с рисками и рекомендациями.
- Отсутствие секретов и реальных имён в интерфейсе.
