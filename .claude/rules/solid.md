# Клиент: SolidJS

**Реактивность (ошибки, которые ИИ делает чаще всего):**
- props **не деструктурировать** — теряется реактивность. Только `props.x`, `splitProps`, `mergeProps`.
- Компонент выполняется **один раз**: ранний `return` по условию не работает → `<Show>`.
- Списки — `<For>` (объекты) / `<Index>` (примитивы), условия — `<Show>` / `<Switch><Match>`.
  Не `.map()` и не тернарники с JSX.
- Производное значение — `createMemo` или функция; `createEffect` только для побочных эффектов
  (DOM, подписки), никогда для вычисления состояния.
- Сигналы вызываются: `count()`, а не `count`.
- Атрибуты: `class` (не `className`), `onInput` для полей, `for` у `<label>`.

**Данные:**
- Запросы — только api-клиент из `@/shared/api` (`openapi-fetch` по сгенерированной схеме). Голый `fetch` запрещён.
- Загрузка — `createResource` или `query` + `createAsync` из `@solidjs/router`; мутации — `action` + `useSubmission`.
- У каждого экрана четыре состояния: загрузка (скелетон), пусто, ошибка (`useToast`), данные.
- Длинные списки — порциями с сервера, фильтры и сортировка на сервере.

**UI:**
- Есть компонент в `@/shared/ui` → используй его. Нет — `bun run new:component <Имя>`.
- Никаких `<select>`, `alert/confirm/prompt`, нативных чекбоксов: Select, Checkbox, Dialog, Toast.
- Строки — `m.key()` из `@/paraglide/messages`. Списки уровня модуля хранят **функцию**: `label: () => m.x()`.
- Стили: раскладка и простой вид — классы темы Tailwind; сложные состояния — CSS Module рядом.
- Импорт между папками — `@/…`; относительный — только внутри своей папки.

**Структура:** `src/app` (вход, маршруты), `src/layout`, `src/shared/{api,ui,lib,styles}`,
`src/features/<домен>/`. Новая страница — `bun run new:page`.
